# ADR 0042: 待機容量超過を通常入力への切替として表示する

状態：専用waiting-demo・実DLLで実装・検証。Issue #4 / draft PR #10。
[ADR 0040](0040-waiting-deadline-and-unadmitted-fallback.md)の未受入れ入力を、
利用者が容量超過と識別できるようにする。

## 問題

待機中に共有救済枠を他の所有者が使い切ると、今回の入力は消費されず通常ホストへ戻る。
入力の重複や原文の置換は避けられるが、救済レコードがない場合は通常のF7案内へ戻り、
何が起きたか画面から分からない。救済レコードがある場合も容量超過の理由は表示されない。

## 決定

専用待機adapterは、4件のローカル上限、共有Recovery予算の`Busy`、Core待機行列の
`Capacity`だけを容量拒否として記録する。期限切れ、保護変化、不正入力、確保失敗は
容量超過と表示しない。Ownerは今回の入力を従来どおり通常ホストへ一度だけ返し、
受入れ済み入力と救済ticketを保持したまま、容量上限による切替をwindow titleへ表示する。
救済が残る場合はF8の確認案内も維持する。新たな待機開始または非待機中のEscで案内を解除する。
期限切れや救済喪失の警告はそれぞれの状態として表示する。

表示は診断デモだけの状態であり、製品の容量値、プロセス間の予算所有者、
超過時の製品キー動作を確定しない。

## 検証

`waiting-demo-test`を59ケースへ拡張した。4件を同じ待機が使い切る既存ケースに加え、
別所有者が共有4枠を先に占有するケースで、救済がない場合も容量表示を維持し、
未受入れ文字を通常ホストで一度だけ入力し、Escで表示を解除することを確認した。
共有枠が満杯でも不正な空文字は容量拒否と表示しない。期限切れも容量表示と混同しない。
実DLL/TSF・合成MSG・試験用Clipboardで検証し、
COM/TSF解除とDLLアンロードも確認した。物理打鍵・一般アプリは未確認である。
ログは`target/issue-4-capacity-feedback-*.log`。
