# ADR 0036: 待機・通常入力の救済を同じ確認画面へ接続する

状態：専用waiting-demo・実DLL・非同期workerで実装・検証。Issue #4 / draft PR #10。
[ADR 0035](0035-waiting-demo-and-record-recovery-ui.md)の確認画面を拡張する。

## 問題

待機入力の未適用レコードが残っている間も、通常入力の同期取引が失敗することがある。
両方は同じEXE共有4枠を使うが、従来は待機OwnerがF8を消費し、通常入力のRescueを開けなかった。
別々のserviceが表示を管理するため、通常入力の警告が巡回用の案内を上書きする経路もあった。

また、保護境界で本文を除去した待機レコードは、確認画面の作成にも入力許可を要求したため、
操作情報を開いて破棄できなかった。コピー処理では、本文の初回取得後に保持期限を過ぎても、
公開直前の検査が保護状態だけを照合していた。

## 表示と操作の所有

waiting-demoではOwnerが1つのViewを所有し、待機レコードを固定index順、通常入力のRescueをその後に並べる。
F8は残る全レコードを巡回する。F9/F10とボタンは表示中の1件だけを破棄/コピーする。
通常入力のRescueしかない場合や、待機Sessionが解放された後も同じ画面を使う。
他のデモでは従来のRescue serviceを維持する。

操作KeyはSourceとticketの組にする。Source::WaitingはSession IDと固定indexを持ち、
Source::Ordinaryはこのeditorの同期取引を指す。独立したslotのticketが同じ値でも区別できる。
通常入力側の更新後も旧ticketは無効で、古い操作を新レコードへ適用しない。
未確認レコードがどちらかに残る場合、新しいF7は確認画面へ案内する。

Rescueは期限/保護のmaintenance、有限なpreviewの複製、正確なticketのcopy/discardを提供する。
Ownerは既存の保護検査と共有予算を利用し、本文を別の救済へ移して予約を取り直さない。
ViewへCOMやEditorを渡さず、callbackはscalar通知だけを返す。
clipboardへ渡す一時本文は有限で、通常入力のRefCell借用を外部呼出しまで持ち越さない。

## 本文の除去と期限

保護境界では両方のpayloadを除去し、古いpreviewを閉じる。
本文を持たない操作情報の表示・破棄には、本文の取得許可を要求しない。
読取専用等で入力検査が拒否する間も、操作情報の画面を維持し、明示破棄で共有枠を返せる。
コピー可能な本文の検査は緩めず、操作情報のF10ではClipboardを呼ばない。

待機レコードのコピーは初回取得・公開直前・処理完了後に同じticketの期限も検査する。
公開直前に期限切れなら拒否し、自動入力や期限の延長を行わない。
通常入力側は従来の期限照合を共通copy helperでも維持する。
Ownerの境界epoch/close検査も通常入力のコピーへ適用する。

入力失敗の警告は、両方の最後のレコードを明示確認した場合だけ解除する。
期限切れや画面の×だけでは解除しない。保護後の操作情報の破棄も本文への再適用を許可しない。
保持期限の取得拒否と所有loopのcleanupを区別し、定刻の物理メモリー消去は保証しない。

## 検証

Windows 11 x64 build 26300 / 通常ユーザーmedium / Rust 1.99.1。
waiting-demo-testは22件から34件へ拡張した。合成MSG/実Viewと試験用Clipboardを使う。

- 待機3件と通常入力1件の巡回、同値ticketの区別、通常入力だけの表示/コピー。
- 1件コピー/破棄、旧通常ticketの拒否、残る救済によるF7拒否、最後の明示確認と期限切れの区別。
- 実DLLの挿入後失敗から通常救済を作る経路、保護による本文除去後の全4件の確認/破棄。
- 通常入力のコピー中の境界/close拒否。救済操作では文書を編集しない。

waiting-input-testは25件から26件へ拡張し、Clipboard公開前に注入時計を10分進めて期限拒否を確認した。
実時間の10分待機や利用者のClipboard変更は行わない。
同期入力174・救済47・通知30・close4、およびRust134件・fmt・Clippy 3構成・build・
load_smoke・self/edit/keyも成功した。ログはtarget/issue-4-unified-recovery-*.log。

専用ACPホストでの経路検証であり、物理打鍵・一般アプリ・製品キーの対応完了ではない。
前面化で未通過のwindow/input/delayedの3検査は維持する。
デモの8秒・共有4枠・救済10分を製品の容量/期限/超過時政策へ昇格させない。
対話操作、一般アプリの保護情報・sink寿命・標準Undo、常駐Broker・配置/認証は引き続き残る。
