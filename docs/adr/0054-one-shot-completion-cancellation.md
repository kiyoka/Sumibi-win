# ADR 0054: 単発Broker結果の完成後取消

2026-10-25 / Issue #4 / PR #10。

単発`BrokerJob`では、子Brokerが成功結果を返した後、所有者が`cancel()`を
呼んでも、取り出した`Completion::outcome()`から成功本文を読めた。
取消状態をCompletionと共有し、明示取消後の読取は`Cancelled`にする。
期限切れの検査も維持し、取消を先に判定する。

`shutdown()`は終了・子process回収の操作としてStopを通知するが、
明示取消の状態は変更しない。終了前に完成していた結果を一律に取消済みと
扱わず、既存の結果保持・容量契約を維持する。

実子Broker・認証済みIPC・実DLL・所有TSF編集の`broker-test`に
`cancel-after-result`を追加した。完成結果を一度確認してから明示取消し、
旧本文が配送されず、元本文とUndo履歴が変わらないことを確認した。
全22ケースとTSF/COM解除・DLLアンロード、単発Jobの容量検査が成功した。

これは診断用の合成本文で確認した単発経路であり、一般アプリの入力受付や
製品の設定・同意変更元を接続した結果ではない。
