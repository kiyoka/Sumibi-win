# ADR 0058: Broker結果の公開と政策更新の順序

2026-10-25 / Issue #4 / PR #10。

Brokerが結果を返す直前に政策を読むだけでは、検査とpipeへの書込の間に
別スレッドの政策更新が入り得る。再利用Channelの通常結果では
`BrokerPolicyGate::authorize_for_publish`が読取guardを返し、版と許可を
確認した後、期限付きのpipe書込が終わるまで保持する。政策更新は書込後に
同じlockの排他guardを取得する。更新が先なら旧版結果を送らず拒否する。
更新を待つ時間は現状の有界なpipe期限に従う。政策更新元のUIへこの待機を
直接載せるかどうかは製品接続時に決める。

Hostの通知カーソルは設定版または認可版のどちらかが進めば最新の
`PolicyChanged`を返す。設定版だけの進行を不正と扱っていた条件を修正した。
未来版のカーソルは拒否する。Protocol、Broker、Hostは設定版だけの更新を
同じ規則で扱う。

このguardはBrokerからのwire書込とBroker内の政策更新の順序だけを
固定する。clientが書込済み結果をいつ読むか、所有TSFスレッドがいつ編集するか
までは保証しない。製品UIの変更完了と全clientへの通知・失効を結ぶには、
通知の配送確認、適用前の所有側policy再検査、未応答clientの切断方針が必要。
診断用のResultとPolicyChangedを同時送信するケースは、clientが通知まで
読み取って旧結果を捨てる回帰として別に維持する。
