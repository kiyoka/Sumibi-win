# ADR 0050: Broker側の政策再検査

2026-10-25 / Issue #4 / PR #10。

再利用Brokerに`BrokerPolicyGate`を追加した。`Ready`後も政策値を固定した
変数だけに頼らず、要求受付時と診断結果の返却直前に設定版・認可版・許可状態を
改めて読む。変更は一つのlock内で公開し、版の巻き戻り、認可版を進めない変更、
利用不能なlockを拒否する。旧版や禁止状態で受けた要求IDは受付済みに進めない。

`revoke-at-accept`診断モードは、合成Convertフレームが実子Brokerへ届いた直後、
受付検査の前に認可版を進めて禁止状態にする。Brokerは古い要求を拒否し、
`PolicyChanged`を返す。`broker-channel-test`は認証済み名前付きpipe上で
`PolicyDenied`、Channel退役、結果・再送なし、子process終了を確認した。
通常版Hostはこの診断モードを拒否する。既存の進行中失効モードもBrokerゲートを
更新してから通知する。通常の合成結果も返却直前に再検査する。

このゲートへ接続する製品の設定・認可変更元と、全接続への通知配送は未実装。
現在の実子検査は固定値を変更するspike fixtureであり、設定UI操作の即時配送を
証明しない。送信直前のclient検査とBroker受付の間に本文がpipeへ入ることはあり、
既に送った本文を取消で回収することもできない。結果返却前の再検査とwriteの間に
将来の別スレッドから政策が変わる競合も残る。通知発行・結果公開・UI操作完了の
順序は製品接続時に固定する。製品通信は引き続き無効である。
