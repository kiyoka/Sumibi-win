# ADR 0039: 救済がなくなった後も入力結果の確認を促す

状態：専用waiting-demo・実DLLで実装・検証。Issue #4 / draft PR #10。
[ADR 0038](0038-owner-wake-for-ordinary-recovery.md)の定期確認で、期限後の画面表示を補強する。

## 問題と変更

waiting-demoのOwnerは救済がなくなると通常のF7案内を表示していた。
通常入力の救済が期限切れになると、入力失敗の状態が残っていても案内が消える。
待機入力の救済がすべて期限切れになった場合も、未確認の操作がなくなったことが伝わらない。

所有loopが救済を確認する前に待機レコードがあったかを保持し、表示するレコードがなくなった時点で
入力失敗の状態または未確認の待機レコードがあれば、文書の結果確認を促す。
待機レコードの喪失は次の所有loopでも表示を維持し、明示Escで追跡を解除した時に消す。
喪失のないレコードを最後まで明示コピー・破棄して確認を終えた場合は、従来どおり通常案内へ戻す。
開始失敗の再試行案内と、まだ待機中の案内は維持する。
警告は本文を復元・再送せず、救済の期限や予算も延長しない。

## 検証と限界

専用ACPデモの実DLL/TSFと合成MSGによる`waiting-demo-test`47件で、
待機・通常入力それぞれの期限切れ後の警告と、次のloopでも維持することを確認した。
workspace Rust134件・fmt・Clippy 3構成・spike buildも成功した。
ログは`target/issue-4-expiry-warning-*.log`。
利用者の実打鍵、一般アプリのタイトル表示、前面化を要する回帰は別の受入条件である。
