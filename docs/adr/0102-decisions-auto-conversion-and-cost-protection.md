# ADR 0102: Decisions自動変換の独立同意・固定窓・費用保護とAPI契約

2026-11-04 / [Issue #7](https://github.com/kiyoka/Sumibi-win/issues/7)
状態: 承認済みの開発方針。[ADR 0001](0001-language-and-ime.md)、[ADR 0071](0071-native-chat-policy-transport.md)、[ADR 0098](0098-manual-conversion-end-to-end-integration.md) に基づき、Sumibi Decisions（自動変換判定）のプロトコル、費用保護、独立同意、および入力キュー制御を決定する。

## 状況

Issue #5（手動変換）および Issue #6（追加候補・ローカル辞書）の完了により、明示操作（`Ctrl+J`）によるオンデマンド変換経路が確立された。
次の段階として、ユーザーが明示的にキーを押さずとも文脈の区切りや確定的な変換契機を検知して自動変換を行う「Decisions自動変換」を導入する。

自動変換はバックグラウンドで高頻度に判定を行うため、以下の重大なリスクと技術的課題が存在する：
1. **費用とトークン消費の暴走**: 高速打鍵や無限ループにより予期せぬAPI利用料が発生するリスク。
2. **プライバシーと同意の分離**: 手動変換（ユーザーが意図して押した時のみ送信）とは異なり、自動変換は打鍵中の文字列を定期的に評価するため、手動同意とは厳格に分離された明示的同意（Opt-in）が必須。
3. **通常打鍵のブロッキング禁止**: 自動変換の判定中であっても、ユーザーのタイピングが引っかかったり遅延してはならない。
4. **古い応答による誤置換（Race Condition）**: 判定中にユーザーが追加入力やBackspaceを行った場合、過去の入力に基づく応答で現在の本文を上書きしてはならない。

## 決定

### 1. 独立同意（Separate Consent）と公式接続先限定
- **既定オフ (Default Disabled)**: 自動変換機能は初期状態で必ず無効（`allowed = false`）。
- **独立同意フラグ**: 手動変換の同意（`manual_conversion_consented`）とは独立した設定項目 `auto_conversion_consented` を `PolicyAuthority` および永続設定（`settings.json`）に新設する。片方を許可しても他方は自動で有効化されない。
- **公式接続先限定**: 自動変換は公式接続先（OpenAI公式エンドポイント等）に限定し、カスタム接続先やプロキシ用の認証情報を流用しない。

### 2. 費用保護（永続カウンタ事前予約、Fail-Closed）
- **上限回数**: 初期の累積判定リクエスト上限を **10,000回**（`MAX_DECISIONS_BUDGET: u64 = 10000`）とする。
- **送信前アトミック永続予約**:
  - リクエストを外部へ送信する**直前**に、永続化ストア（設定ファイル等）のカウンタをインクリメントして保存を完了する。
  - カウンタの永続化に失敗した場合、通信は一切行わず即座に中断する（Fail-Closed）。
- **取消・失敗時も不返却**:
  - 通信エラー、タイムアウト、ユーザーによる取消、または判定破棄が発生した場合でも、予約したカウントを巻き戻さない（保守的費用評価）。
  - 再起動や複数プロセスの同時起動によっても上限回数を超過しない。
- **回数と請求額の分離**: カウンタは「HTTPリクエスト回数」であり、金額（円/ドル）と混同させない。

### 3. 固定200ms窓と状態バッファ制限
- **固定窓 (`WINDOW_DURATION: Duration = 200ms`)**:
  - 後続の打鍵によって窓を無制限に延長しない。単調時計（`Instant`）により厳格に時間を計測。
- **バッファ容量制限**:
  - 1バッチあたりの最大状態数: **32状態** (`MAX_STATES_PER_BATCH = 32`)
  - 未送信キューの最大状態数: **256状態** (`MAX_PENDING_STATES = 256`)
  - 1状態あたりの最大書記素数: **512書記素** (`MAX_GRAPHEMES_PER_STATE = 512`)
  - 上限超過時は古い未送信状態を速やかに破棄し、通常打鍵を優先する。

### 4. Decisions API 契約と回答検証
- **モデル**: `gpt-4o-mini`（低遅延・経済性）
- **回答スキーマ**:
  ```json
  {
    "decisions": [
      {
        "id": 1,
        "should_convert": true,
        "confidence": 0.95,
        "converted_text": "日本語"
      }
    ]
  }
  ```
- **回答照合ルール**:
  1. `id` は送信した状態ID集合と完全一致すること（配列順序に依存しない照合）。
  2. `confidence` は有限の浮動小数点数値であり、`0.0 <= confidence <= 1.0` であること（NaN, Infinity は拒絶）。
  3. `should_convert == true` かつ `confidence >= 0.5`（判定閾値）の場合のみ変換候補を採用。
  4. 重複ID、未知のフィールド、不正な型が含まれる場合はレスポンス全体を破棄（InvalidResponse）。

### 5. 入力優先と手動優先の直列化
- **通常打鍵の即時反映**:
  - 自動変換判定の送受信中であっても、TSFへの通常打鍵はブロックせず即時ドキュメントに反映する。
- **手動変換（`Ctrl+J`）の絶対優先**:
  - 手動変換要求が発生した瞬間、進行中の自動判定タスク・キューは直ちに破棄（Cancel）される。
- **対象・世代再検証**:
  - 判定結果が到着した際、ドキュメントの現在の世代（Revision）、選択範囲、および原文が完全一致する場合のみ置換を実行する。少しでも不一致があれば結果を静かに破棄する。

## 影響と検証
- `sumibi-core`: Decisions 関連のデータ型（`DecisionItem`, `DecisionBatch`）、状態バッファ、バリデーションロジックの実装。
- `sumibi-host`: 費用保護カウンタ（`BudgetManager`）、独立同意、Decisions API リクエスト生成・パース。
- `sumibi-tip`: 非同期判定結果の安全な受け入れ、手動変換との優先制御、1-step Undo。
- ハーネス検証: 模擬 HTTP による全状態遷移（同意拒否、予算上限到達、通信エラー、破棄、手動割り込み）の網羅的自動テスト。
