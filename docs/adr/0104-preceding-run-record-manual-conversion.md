## 1. 背景と課題

Sumibi の macOS 版では、ユーザーがテキストを手動で反転選択（ドラッグや `Shift+←`）しなくても、ローマ字を普通に打鍵してそのまま `Ctrl+J` を押せば、直前の入力文字列が即座にかな漢字変換される。

一方、Windows 版の初期実装では、保護入力欄での安全性を担保するため「選択範囲が存在しない（キャレットが単一位置にある）場合は変換を Fail-Closed で拒絶する」仕様となっていた。これにより、実機テストにおいて「テキストを選択しないと変換できない」という macOS 版との操作性ギャップが生じていた。

macOS 版と同等の入力体験を提供しつつ、Windows / TSF 環境における堅牢性と安全境界を両立するインターフェースの実現が求められた。

---

## 2. 検討された方式

| 方式 | 概要 | 長所 | 短所 / 判定 |
| :--- | :--- | :--- | :--- |
| **方式 A: 逆方向文脈探索** | `Ctrl+J` 押下時にキャレットから前方に文書バッファを探索し、ローマ字境界を切り出す | 実装が `Ctrl+J` 契機のみで完結 | アプリ側の `ITfRange::GetText` 実装依存が高く、先行する文脈との境界誤認や不必要なドキュメント読み取りのリスクがある |
| **方式 B: 打鍵記録方式**（採択） | ローマ字キー入力をパッシブに記録し、`Ctrl+J` 押下時にキャレット直前のドキュメント文字列と厳密照合して選択範囲に昇格 | ユーザーが打鍵した確実な文字数・内容のみを検証・置換するため、誤置換・情報漏洩リスクがゼロ | 打鍵監視およびキーイベントハンドリングの実装が必要 |
| **方式 C: コンポジション常用** | 常に TSF コンポジション（下線表示）を開始して未確定文字列として保持 | 従来の日本語 IME と同一の挙動 | 「打鍵即時反映（直接入力）」という Sumibi のコア哲学と乖離し、インライン描画や確定・キャンセルの複雑性が激増 |

## 3. 決定事項

### 3.1 方式 B（打鍵記録方式）の採用

1. **パッシブ打鍵記録 (`RunRecord`)**:
   - `ITfKeyEventSink` を通じてキー入力をパッシブに観測。キーは一切横取り（消費）せず、アプリにそのまま通過させる。
   - 記録対象：英数字および一般的なローマ字・記号（ASCII 文字）。
   - 純粋修飾キー（`Ctrl`, `Shift`, `Alt`, `Win` 等）は記録を破棄せず維持（`Ctrl+J` 押下直前の `Ctrl` 押下で記録が消えるのを防止）。
   - 記録上限：256 ユニット。上限超過時は安全のため記録をポイズン（無効化）し、次の境界まで保持しない。
   - 境界での破棄：矢印キー移動、Enter、Esc、Space（語境界）、マウス操作、コンテキスト破棄、保護状態検出時は記録を直ちにクリア。

2. **キャレット直前の検証と自動選択化 (`select_preceding_run`)**:
   - `Ctrl+J` 押下時、明示的な選択範囲（`!caret.IsEmpty()`）が存在する場合は、既存の選択範囲変換を優先（後方互換性維持）。
   - キャレットが単一位置（Collapsed）の場合、記録された文字数分だけ `expanded.ShiftStart` で前方に拡張。
   - 拡張された範囲のテキストをドキュメントから読み取り、記録された文字列と**1文字の狂いもなく完全一致（`text == expected`）した場合のみ**、ドキュメントの選択範囲として昇格設定（`SetSelection`）。
   - 不一致や境界異常が発生した場合は即座にアボートし、ドキュメントを一切変更しない。

3. **保護入力欄での絶対防御境界 (Fail-Closed)**:
   - パスワード欄、PIN 入力、ReadOnly、一時コンテキスト（`TS_SS_TRANSITORY`）などでは、打鍵の記録自体を行わず、変換要求も拒絶。

### 3.2 TSF キーイベントシンクの Windows 11 アプリ統合

実機検証の結果、Windows 11 のメモ帳（`Microsoft.WindowsNotepad` / RichEdit コントロール）など一部の TSF アプリケーションでは、**`ITfKeyEventSink::OnTestKeyDown` が呼ばれず、直接 `OnKeyDown` が呼ばれる**挙動が判明した。

これを解決するため、以下の重複除外判定を導入：
- `OnTestKeyDown` 呼び出し時、`(VirtualKey, Flags, MessageTime)` を `Cell` に記録。
- `OnKeyDown` 呼び出し時、直前の `OnTestKeyDown` と同一イベントであれば記録済みとしてスキップ。
- `OnTestKeyDown` を経由せずに `OnKeyDown` が直接呼ばれた場合は、`OnKeyDown` 側で安全に打鍵記録を実行。
- これにより、`OnTestKeyDown` を呼ぶアプリと直接 `OnKeyDown` を呼ぶアプリの双対環境において、1文字たりとも重複・欠落することなく打鍵が追跡される。

## 4. セキュリティ・互換性・影響

1. **機密情報の局所性**:
   - 打鍵記録は TIP プロセス内部のローカルメモリ（`RefCell<RunRecord>`）にのみ一時保持され、外部プロセスへの送信やファイル出力は行われない。
   - 変換要求が発生しなかった記録は、フォーカス外れやキャレット移動時に即座にゼロクリア・破棄される。
2. **既存機能との完全な互換性**:
   - 従来の「テキストを選択して `Ctrl+J`」という操作フローも完全に維持される。
3. **誤置換の完全防止**:
   - ドキュメント原文と記録が一致しない場合は一切置換を行わないため、古い打鍵バッファによる予期しないテキスト置換事故が発生しない。
