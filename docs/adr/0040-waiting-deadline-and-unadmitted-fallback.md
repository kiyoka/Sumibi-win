# ADR 0040: 待機期限の表示と未受入れ入力の安全な通常経路

状態：専用waiting-demo・実DLLで実装・検証。Issue #4 / draft PR #10。
[ADR 0035](0035-waiting-demo-and-record-recovery-ui.md)の容量超過と期限切れ時の通常入力を補強する。

## 問題

変換待機中に入力を一件も受け入れず8秒の期限に達すると、Ownerは通常のF7案内へ戻り、
期限切れを利用者へ示さなかった。期限直後の未受入れ文字や容量超過の文字は通常ホストへ渡るが、
F7が原文を選択したままだと、その文字が原文全体を置き換えた。
例えば`nihongo`からF7を始め、容量超過で`e`を渡すと、従来は文書が`e`になった。

## 変更

Ownerは待機期限をserviceとadmitの両方で検出し、変換待機の期限切れを表示する。
次の所有loopでも案内を維持し、新しいF7開始またはEscで解除する。
既に結果が適用された可能性もあるため、原文保持を無条件には表示せず文書の結果確認を促す。
救済が残る間は救済案内を優先し、未確認救済の喪失案内も優先する。

未受入れのイベントを通常ホストへ渡す前に、専用ホストの選択と通知が開始時から安定し、
まだ待機変換の結果を文書へ適用していない場合だけ、F7で選択された範囲の末尾へcaretを移す。
要求を取消して受入れ済みイベントを救済へ移した後にも状態を再照合し、
caret移動に失敗した場合は入力を重ねて実行しない。
これにより容量超過の`e`は`nihongoe`となり、受入れ済みイベントの救済は残る。
期限直後の未受入れ文字は一度ずつ入力され、Backspaceは原文末尾から一字だけ削除する。
期限直後のEnterは未受入れなので通常ホストへ一度だけ渡す。
受入れ済みのEnterを遅れて再送する処理は追加しない。
入力がないまま所有ループが期限を検出した場合も、同じ安定性条件を期限前後に照合し、
原文の選択をその時点で解除する。これで後から届く通常文字・Backspace・Enterが
期限切れの原文選択を引き継がない。受入れ済みの文字は救済へ残す。
その後の通常編集で保護履歴が変われば救済本文を除去し、操作記録だけを残す。
Escを消費して明示取消する場合も、待機中の安定した原文選択を取消前後に照合し、
原文末尾へcaretを移す。後続の通常文字が原文全体を置換しない。
移動や修飾ショートカットなど元のキーをホストへ渡す停止経路は変更しない。

## 検証と限界

`waiting-demo-test`を47件から57件へ拡張した。実DLL/TSF・合成MSG・試験用Clipboardで、
空の待機期限、期限時の文字・Backspace・Enter、容量超過の原文保持と共有救済、
入力なしで期限が切れた後の文字・Backspace・Enter、受入れ済み文字の救済と後続編集、
Esc明示取消後の文字と受入れ済み救済の保持、
文書本文・Undo回数・Enter一度だけの通過、期限表示の維持と解除を確認した。
`waiting-input-test`26件、workspace Rust134件・fmt・Clippy 3構成・spike buildも成功した。
ログは`target/issue-4-deadline-feedback-*.log`。
入力なしの期限検出を加えた4ケースのログは`target/issue-4-idle-timeout-*.log`。
Esc後の通常入力を加えた2ケースのログは`target/issue-4-escape-fallback-*.log`。

caret補正は専用の協調ACPホストだけで行う。一般アプリの選択・Undo・実打鍵、
製品の待機容量/期限/超過時動作をこれで確定した意味ではない。
