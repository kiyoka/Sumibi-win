# ADR 0092: 常駐 Host のシステムトレイ（通知領域）統合と最小化常駐

2026-11-03 / [Issue #4](https://github.com/kiyoka/Sumibi-win/issues/4) / [draft PR #10](https://github.com/kiyoka/Sumibi-win/pull/10)。
状態: 承認済みの製品 Host 機能拡張。システムトレイ通知領域への常駐、タスクバー最小化、およびコンテキストメニューを実装する。

## 状況

[ADR 0090](0090-default-gui-host-entry.md) により、製品 Host（`sumibi-host.exe`）の引数なし起動で送信管理画面（`consent_window`）または初期設定画面（`settings_window`）が自動起動し、バックグラウンドでの TIP 待受が開始されるようになった。
しかし現在の `consent_window` は通常のタスクバーウィンドウとして表示され続けるため、以下の課題があった：

1. **タスクバーの占有**:
   一般アプリで文章入力を行っている最中もタスクバーに常時表示され、作業領域を圧迫する。
2. **誤終了のリスク**:
   ウィンドウの「×」閉じるボタンを押すとプロセス全体が終了してしまい、意図せずバックグラウンドの変換待受が切断される。
3. **常駐 IME Host としての操作性**:
   タスクバー通知領域（システムトレイ）からワンクリックで送信管理画面を呼び出したり、設定画面を開いたり、明示的に終了できる標準的な常駐 UI が求められる。

## 決定

### 1. システムトレイ通知領域アイコン（`TrayIcon`）の統合

- `consent_window` 起動時に、Win32 `Shell_NotifyIconW`（`NIM_ADD`）を用いてタスクバー通知領域に Sumibi Host アイコンを登録する。
- ツールチップに `"Sumibi Host (待受中)"` を設定し、バックグラウンド待受中であることを視覚的に明示する。
- `TrayIcon` の Drop 実装で `NIM_DELETE` を呼び出し、プロセス終了時やウィンドウ破棄時にゴーストアイコンを残さず確実にクリーンアップする（RAII）。

### 2. ウィンドウの最小化常駐とタスクバー非表示

- **閉じる（`WM_CLOSE`）ボタンの挙動**:
  - ウィンドウの「×」ボタンを押した際、直ちにプロセスを終了するのではなく、ウィンドウを非表示（`SW_HIDE`）にしてトレイアイコンへ格納し、バックグラウンド待受を継続する。
  - プロセスを明示的に終了したい場合は、画面上の「Host を終了」ボタン（ID 3）またはトレイメニューの「終了」を選択する。
- **最小化（`SC_MINIMIZE`）の挙動**:
  - ウィンドウの最小化ボタンが押された場合も、同様に `SW_HIDE` でトレイへ格納する。

### 3. トレイアイコンの対話操作とコンテキストメニュー

- **左クリック / ダブルクリック（`WM_LBUTTONUP` / `WM_LBUTTONDBLCLK`）**:
  - 送信管理画面を再表示（`SW_SHOW` / `SW_RESTORE`）し、フォアグラウンドへ復帰（`SetForegroundWindow`）させる。
- **右クリック（`WM_RBUTTONUP` / `WM_CONTEXTMENU`）**:
  - ポップアップメニュー（`TrackPopupMenu`）を表示：
    - `送信管理画面を開く (&O)`: ウィンドウを表示してフォアグラウンド化。
    - `設定画面を開く (&S)`: 設定編集ウィンドウ（`settings_window`）を呼び出し。
    - `---`（セパレータ）
    - `Host を終了 (&X)`: Host サービスの安全な停止シーケンスを開始し、プロセスを終了。

## 影響と検証

- 一般アプリ使用中にタスクバーを常時占有することがなくなり、一般的な Windows IME/常駐ツールと同様に自然に通知領域に格納される。
- 誤ってウィンドウを閉じても待受が維持され、トレイアイコンからいつでも送信管理画面や設定画面を復帰できる。
- 既存の `lib.rs`（`#![forbid(unsafe_code)]`）の不変条件を完全に維持し、Win32 UI 固有の処理は `sumibi-host` のバイナリ側（`consent_window.rs` / `tray.rs`）に限定する。
