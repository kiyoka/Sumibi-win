## 共通契約と順序

| 動作 | Windowsでの扱い |
| --- | --- |
| 通常の英字入力・控えめな下線 | 最初のTSF試作。文字入力とホスト操作を壊さない |
| 初回1候補を自動確定 | 手動変換の最初の縦断実装。模擬サービスで先に確認 |
| 元原文＋現在結果で追加候補 | 次段階。現在結果を先頭にし、取得だけで置換しない |
| 候補最大12、辞書追加最大10 | Mac現行互換の提案値。SPECの追加10件との差は未解決なので合意済みとしない |
| Enter・Esc・選択範囲変換 | 試作から検証。通常Enterは変換せず原文確定後ホストへ渡す |
| 待機中の文字入力 | 順序付き待ち行列。対象変更時は別欄へ流さず文字を救済 |
| 待機中のEnter等 | Mac同様、ホストへの遅延再送は初期実装で行わない案。未適用を表示し、仕様との差を明示 |
| Undo | 1回で原文へ戻すことを受入目標にする。Macの2回書込を機械的に移さない |
| Decisions自動変換 | 手動経路の成立後。入力即時処理と古い応答破棄。手動待ち行列を共用しない |
| APIキー・同意・固定エラー | 初回の実通信までに実装。エラー解除が次の変換の条件にならない |
| ユーザー辞書 | 100件・保存2,000文字、送信合計1,000文字は別判定 |
| 記号・同音異義語 | 中黒→Mozc→Sudachiで追加10件。出所・LICENSE・固定元データを保持 |
| 一時本文デバッグ | 後続。明示オン・メモリだけ・再起動後オフ。通常ログには本文なし |

## 未実装要件とWindows固有事項

周辺文脈、文体プリセット、変換テストUI、一般的な利用状況はMacでも未実装の要件。
初期のWindows互換範囲へ自動で追加しない。
Ctrl＋Jは試作の変換キー案。右Commandの短押しを右Alt／Windowsキーへ自動対応させない。
無変換・変換キー、US/JIS配列、Windows Terminalでのキー配送は実機で決める。
Emacs除外は意図を引き継ぐが、プロセス識別と対象一覧はWindowsで別設計する。

Macの0.3秒コントローラー寿命判定、相対末尾の補正、client poke、AppKit窓、Keychain名、
Developer ID、公証、旧Jev設定移行はWindowsの必須仕様にしない。
Macの長文読取不能や短文不一致は入力先の異常系テストへ使い、再現を製品仕様としない。
DecisionsのAPI契約は実装着手時に公式資料と再照合する。この設計段階では実APIを検証していない。

## 受入ケース

- 初回／追加／選択、空・重複候補、連打、失敗、タイムアウト、Esc後の遅延応答。
- 新規入力・Backspace・移動・別欄・別アプリ・同意変更・EXE再起動で旧結果を拒否。
- 読取不能、同長別内容、前方に同一原文、部分一致、古い範囲、絵文字・結合文字。
- 候補の順序・出所・記号保持、辞書欠損、API失敗時に辞書だけで代替しない。
- 自動変換の固定200ms窓、32状態分割、256状態上限、10,000回初期上限、取消も計数。
- Notepad、VS Code、Chromium系入力欄、Windows TerminalをOS・版・CPU・権限別に記録。
- 通常／パスワード／読取専用、複数ウィンドウ、IME切替、1回のUndo、登録・更新・解除。

これらは計画であり、Windowsでの成功記録ではない。Macのテスト件数をWindowsの検証実績へ転記しない。
